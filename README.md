# SCHDK — інструменти для «Що? Де? Коли?»

SCHDK — це набір браузерних і десктопних застосунків для Windows, призначених
для підготовки та проведення ігор «Що? Де? Коли?». Репозиторій
організовано як pnpm-монорепозиторій на основі React, TypeScript, Vite,
Electron і Turborepo.

Редактор створює переносні файли `.schdk` із 36 питаннями, а розділ «Провести
гру» відкриває готовий пакет і проводить його як повноекранний покроковий
сценарій.

## Можливості гри

- Відкриття `.schdk` через діалог, перетягування або список недавніх пакетів.
- Перевірка готовності та spoiler-free екран зі статистикою перед стартом.
- Повноекранний wizard через номер питання, роздатку, текст питання,
  хвилинний таймер, коментар до відповіді та відповідь.
- Звукові сигнали на старті таймера, за 10 секунд і після завершення часу з
  гучністю, що налаштовується (40% за замовчуванням).
- Керування кнопками або `Space` / `PageDown` / `ArrowRight` і
  `Backspace` / `PageUp` / `ArrowLeft`.
- Візуальний редактор макета з перетягуванням усіх елементів і автоматичним
  застосуванням їхніх позицій під час гри.
- Фінальний екран із поверненням до списку ігор.

## Можливості редактора

- Створення пакета з трьома раундами по 12 питань.
- Редагування назви пакета, тексту питання, відповіді, альтернативних
  відповідей, текстової роздатки або зображення-роздатки, невирішеного коментаря
  та приватних приміток для ведучого.
- Копіювання всіх полів питання як JSON і вставлення їх в інше питання після
  підтвердження.
- Відкриття файлів `.schdk` через діалог вибору або перетягуванням у вікно.
- Збереження пакетів як стиснених ZIP-архівів із розширенням `.schdk`.
- Відкриття старих `.schdk` у вигляді звичайного JSON із перетворенням на ZIP
  під час наступного збереження.
- Збереження аварійної браузерної чернетки в `localStorage` і пропозиція
  відновити її після перерваного сеансу редагування.
- Відображення до 20 недавніх пакетів із назвою пакета та назвою файла.
  Десктопні застосунки повторно відкривають справжній файл із диска, а браузерні
  — останню збережену локальну копію з IndexedDB.
- Автоматичне збереження десктопних змін у відкритий файл, зокрема під час
  повернення на початковий екран або закриття застосунку.

Повний опис формату файлу міститься в
[docs/GAME_PACKAGE.md](docs/GAME_PACKAGE.md).

У корені репозиторію виконайте:

## Підключення Google Диска

Google Диск необов'язково синхронізує налаштування редагування та проведення
гри між веб- і десктопним застосунками. Локальне збереження продовжує працювати
без підключення. Файли `.schdk` поки що не синхронізуються.

Веб- і десктопний застосунки вже містять свої публічні OAuth client ID.
`VITE_GOOGLE_WEB_CLIENT_ID` і `GOOGLE_DESKTOP_CLIENT_ID` потрібні лише для
їхньої заміни під час розробки.

Вебзастосунок зберігає access token лише в пам'яті й після завершення його дії
просить підключитися знову. Десктопний застосунок відкриває системний браузер і
зберігає refresh token через захищене сховище операційної системи.

## Запуск повного вебзастосунку

```powershell
pnpm dev
```

Відкрийте <http://127.0.0.1:5173>. Команда запускає один сервер розробки Vite;
Розділи «Провести гру» і «Редагувати пакети питань» завантажуються окремими
JavaScript-бандлами після першого відкриття:

| Адреса                  | Застосунок                  |
| ----------------------- | --------------------------- |
| <http://127.0.0.1:5173> | Об'єднаний застосунок SCHDK |

Порт фіксований. Якщо він зайнятий, команда завершиться з помилкою.

Після відкриття пакета браузер додає його ідентифікатор до параметра
`?package=`. Перезавантаження такого URL автоматично відкриває локальну копію з
IndexedDB у тому самому браузері та профілі. Посилання не надає браузеру доступу
до довільного файла на диску й перестане працювати, якщо локальну копію видалено.

## Запуск повного десктопного застосунку

```powershell
pnpm dev:all-desktop
```

Команда збирає спільну вебоболонку з лінивими бандлами гри й редактора питань,
збирає головний процес Electron та запускає розгорнутий на весь екран
десктопний застосунок `SCHDK`. Це єдиний десктопний застосунок проєкту.

Десктопний редактор має доступ до справжніх шляхів файлової системи. Тому
недавній пакет відкриває поточний файл із диска, а не кешовану браузерну копію.
Після повторного запуску спільний застосунок відновлює останній активний розділ,
а редактор намагається знову відкрити попередній файл і вибране питання. Якщо
файл переміщено або видалено, застарілий стан очищується й редактор показує
помилку замість повторних невдалих спроб.

## Окремий запуск вебзастосунків

Для роботи лише з однією частиною проєкту використовуйте такі команди:

| Команда               | Результат                                               |
| --------------------- | ------------------------------------------------------- |
| `pnpm dev:editor-web` | Запускає окремий браузерний редактор через Vite.        |
| `pnpm dev:host-web`   | Запускає окрему браузерну оболонку ведучого через Vite. |

Окремі Vite-команди використовують стандартний механізм вибору порту Vite.
Для перевірки навігації між застосунками краще запускати спільну команду
`pnpm dev`.

## Робота з файлами в браузері та на десктопі

В обох середовищах працює той самий React-редактор, але доступ до файлів
відрізняється.

### Браузер

- Якщо браузер підтримує File System Access API, збереження використовує його.
- В інших браузерах збереження завантажує новий файл `.schdk`.
- Повернення на початковий екран за наявності змін пропонує зберегти пакет.
- Незбережені зміни зберігаються як аварійна копія в `localStorage`.
- Недавні пакети містять останні збережені копії в IndexedDB і не отримують
  необмеженого доступу до початкових файлів на диску.

### Десктоп

- Electron відкриває вибраний `.schdk` за шляхом у файловій системі.
- Зміни автоматично записуються назад у дозволений користувачем файл.
- Закриття вікна очікує завершення збереження. У разі помилки можна повторити
  збереження, закрити без збереження або скасувати закриття.
- Недавні пакети зберігають дозволені шляхи й читають актуальний вміст із диска.
- Заголовок вікна містить назву відкритого файлу.

## Збирання готових застосунків

Зібрати всі пакети робочого простору:

```powershell
pnpm build
```

Turborepo збирає пакети в порядку залежностей, кешує локальні результати й
залишає їх у каталозі `dist` відповідного пакета. Пакування Electron завжди
виконується окремо: файли з `dist/release`, зокрема `.exe`, до кешу не потрапляють.

Electron-пакет наразі використовує розпакований каталог electron-builder,
а не створює інсталятор. Виконуваний файл Windows розташований тут:

```text
packages/all-desktop-app/dist/release/win-unpacked/ЩДК.exe
```

Для збирання окремого пакета скористайтеся фільтром робочого простору pnpm:

```powershell
pnpm --filter @schdk/editor-web-app build
pnpm turbo package --filter @schdk/all-desktop-app
```

Під час прямого збирання десктопного пакета спершу потрібно зібрати його
вебзалежність. Коренева команда `pnpm build` і всі десктопні `dev`-скрипти вже
враховують порядок залежностей.

## Коротко про формат `.schdk`

Сучасний файл `.schdk` — це ZIP-архів з одним UTF-8-файлом `game.json`.
Кореневий об'єкт містить:

- `format: "schdk-game-package"`;
- `version: 2`;
- назву пакета `title`;
- рівно 36 упорядкованих елементів `questions`.

Кожне питання має тип `standard`, `blitz-2x30` або `blitz-3x20`, масив
`questionParts`, одну відповідь `answer`, масив `alternativeAnswers` і масив
`wrongAnswers`.
Зображення-роздатка, невирішений коментар і примітки для ведучого є
необов'язковими. Формат потрібно змінювати в спільному контракті, описаному в
[docs/GAME_PACKAGE.md](docs/GAME_PACKAGE.md), а не в коді окремого застосунку.

## Усунення проблем

### `pnpm dev` повідомляє, що порт уже використовується

Зупиніть процес, який використовує порт 5173, і повторіть команду.

### Недавній браузерний пакет не містить незбережених змін

Це очікувана поведінка: недавні пакети представляють останню збережену копію.
Незбережені зміни зберігаються окремо як аварійна чернетка й пропонуються до
відновлення під час наступного відкриття цього пакета.

### Недавній десктопний файл не відкривається

Можливо, файл переміщено або видалено поза SCHDK. Виберіть його повторно в
новому розташуванні. Недоступний запис буде вилучено після невдалої спроби
відкриття.

### Перед запуском десктопного застосунку відбувається повторне збирання

Десктопні скрипти розробки спеціально збирають вебпакет перед запуском
Electron. Наразі вони не використовують гаряче перезавантаження Electron.
